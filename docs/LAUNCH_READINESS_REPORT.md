# 问山上线准备检查报告

## 当前状态

现有 Next.js 与 v1.6 交互已进入本地上线候选。项目原地初始化 Git，当前分支为 `dev/launch-readiness`，首次提交、远程仓库绑定和实际发布待授权。代码包含 GitHub CI 与 PR 模板，Vercel 的生产分支、预览保护和 GitHub 的代码所有者审批由一次性账号设置完成。

可复用的业务接口为 `/api/companion` 与 `/api/reading`。新增 `/api/health` 报告版本、环境准备状态与可用 Provider。前端仍走原来的业务入口。

## 实现与核验

| 项目 | 本轮结果 |
| --- | --- |
| 构建与类型 | Next.js 生产构建、独立 TypeScript 检查通过 |
| 回归测试 | 24 项单元测试通过。桌面 Edge 和模拟手机 20 项通过，6 项因只针对另一尺寸而按配置跳过 |
| 数据迁移 | 三个 SQL 版本依次应用到隔离的 PGlite PostgreSQL。已从备份恢复一组模拟旧数据，在同一套约束下通过导入回滚与落库测试 |
| 旧数据 | 模拟迁移保留绑定、180 XP、相伴记录、身形、月灯及已存历史；首次云端凭据采用已验证邮箱，原旧密码哈希留在本地副本 |
| 跨账号隔离 | 第二人读取第一人的灵宠、事件、起卦、历史、资料、道具均为空；跨人修改昵称和删除记录影响零行；伪造道具与匿名访问被拒绝。删除第一人的测试 Auth 后，第二人数据仍可读 |
| Auth 协议 | 本地模拟 Supabase API 验证了注册后需确认、验证码换会话、有效令牌接受、伪造令牌拒绝与过期后刷新 |
| Gemini 传输 | 本地模拟 SSE 拆帧、忽略思考段、流式呈现、模型限额与截断降级；最终结果仍由本地起卦、经文和现有校验确定 |
| Ollama 实测 | 本机 qwen3:4b 完成一条「离之艮」流式解读，首段 85 ms，总耗时约 14.5 秒。其中一节由内置释意补足 |
| 共享限额 | 同一配额库 8 次并发申请只放行 3 次，分钟与日配额分别触顶，0 可关闭云端调用 |
| 生产运行时 | 本机 Next.js 成品以演示配置启动时健康检查为 200；切到 Gemini 但保留空凭据时健康检查为 503，问卦仍返回带状态的内置释意。未同意发送时返回显式同意提示 |
| 密钥边界 | Gemini Key、Auth 管理密钥和数据库连接只在服务端读取；Gemini 发送范围由本次点击确认，个人出生日期和画像字段不随云端请求发送 |

## 正式开通前的待验事项

- GitHub 代码所有者审批与必过检查、Vercel 受保护 Preview、正式域名自动发布和上一版本回退都需要连接用户账号后实测。
- 正式 Supabase 项目的 SMTP、邮箱注册、刷新/退出、事务池角色、生产连接证书和两个账号隔离需要在独立预览项目验收。当前主机未配置 Supabase 连接与 CLI，SQL 和 Auth 协议结果来自本地测试环境。
- 本机未配置 Gemini Free Tier Key。真实模型可用性、中文解读质量和项目额度需要在用户提供独立测试配置后，按发布手册做一条固定问题的实测。
- 生产备份、恢复演练及正式迁移仍待用户许可。离线验证使用合成记录，升级待执行。

环境、一次性操作、发布及数据恢复详见 [发布与恢复手册](RELEASE_RUNBOOK.md)。
