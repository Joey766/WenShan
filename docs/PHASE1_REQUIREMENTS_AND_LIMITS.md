# 问山｜第一阶段开发目标及安全规则

当前用户已明确授权在 `塔罗project` 本地目录直接开发 **第一版可运行原型**，与 v1/v2 较早的“暂不开发最终页面”说明不同：以最新明确需求为准。

## 路线
首页（选宠）→ 从中央雾道推进 → 问心台（提问，三枚铜钱投掷六次，自下而上显示爻）→ 六爻升空穿云 → 观卦阁（可核对本卦/动爻/变卦、基于确切原文的 AI 或 mock 解读、追问）→ 灵宠居所（同一宠物跨页面，游客本地保存，简单互动）。

## 引擎边界
- 3 枚铜钱各自等概率得到 2 或 3，每轮相加得 6/7/8/9，概率分别为 1/8、3/8、3/8、1/8，不能把四个爻值作为等概率直接抽取。
- 6 老阴、7 少阳、8 少阴、9 老阳；老阴/老阳变化；自下而上立六爻，按二进制上下卦正确查六十四卦。
- 同一组三枚铜钱的正反/数值/总和必须一致。
- AI 负责解释与追问，不算卦、不伪造卦辞。没有校对来源时宁可标记“资料待核验”，不要编造古籍原文。
- 初版可本地 mock 解读与可选 Ollama 服务端连接，未发现运行中的 Ollama 时必须优雅降级，不嵌入任何 API key。
- 仅客户端保存游客宠物，不强制注册；若做跨设备登录，视后续授权再定。

## 用量安全阈值
- 5 小时剩余 **<=5%** 或每周剩余 **<=3%** 时停止新工作。
- 不得假定自己能自动读取实时剩余百分比；官方 Codex CLI `/status` 可查看会话/用量，具体显示因客户端版本与账户而异。若不可访问，不要编造，要求用户提供界面数值。
- 检查用量前后如接近阈值立即保存进度、写 docs/PROJECT_PROGRESS.md 和 docs/RESUME.md，再停手。
- 用户说的“下次恢复继续”是 **用户重新启动 Codex 后在原目录续做**；不允许无授权使用隐藏定时器、额外 API/买额度绕限。
- 不覆盖原始 ZIP/GIF，先建立清单，疑似同名 %URL 编码 ZIP 用内容 SHA256 去重；安全解压、防目录穿越。
